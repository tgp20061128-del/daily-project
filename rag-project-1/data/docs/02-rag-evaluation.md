# RAG 评测：如何衡量一个 RAG 系统好不好

## 为什么需要评测

没有评测的 RAG 系统无法改进。凭感觉调切分大小、换 embedding 模型、加 reranker，都不知道到底变好还是变坏。正确的做法是先建评测集：准备 100 条左右有标准答案的问题，覆盖事实问答、跨文档综合、多轮追问、拒答和格式引用几类，再用固定指标跑分，每次改动都对比前后分数。

## RAGAS 指标

RAGAS 是常用的 RAG 评测框架，核心指标有四个。Faithfulness（忠实度）衡量答案是否完全由检索到的上下文支撑，答案里每句话都应在上下文中找到依据。Answer relevancy（答案相关性）衡量答案是否真正回答了问题。Context precision（上下文精确率）衡量检索到的块里有多少是真正相关的。Context recall（上下文召回率）衡量标准答案所需的关键信息有多少被检索到了。

## 基线对比与消融实验

每次优化都要做基线对比：先记录当前系统的分数，再只改一个变量（比如只换切分大小，或只加 reranker），重新跑分。一次只改一个变量的实验叫消融实验，它能告诉你每个优化到底贡献了多少。没有基线对比的“优化”只是猜测。

## 失败案例分析

分数之外还要看失败案例。把答错的题按原因分类：检索没召回、召回了但排序靠后、上下文是对的但模型答错了、应该拒答却编了答案。分类之后才能知道下一步该改检索、改提示词还是改拒答阈值。

# Embedding 模型与重排

本文为自写样例文档，非权威来源，仅用于跑通 RAG 链路。

## Embedding 在 RAG 里起什么作用

Embedding 模型负责把文字变成向量，是向量检索的底座。问题变成向量，文档块变成向量，两者距离越近，语义越相关。模型选得不好，后面的融合、重排再努力也补不回来，因为粗排阶段已经把关键块漏掉了。模型选得太重，编码速度和显存占用又会拖慢整个链路。选型不是挑分数最高的模型，而是挑在自己的知识库、自己的问题分布、自己的延迟预算下综合最合适的模型。样例库的经验是，换模型带来的召回率变化通常在三到八个百分点之间，比调切分、调权重的影响更大，值得花时间认真测。测试方法也很明确：固定切分、固定融合、固定重排，只换 embedding 模型，在同一评测集上对比召回率和延迟。一次只换一个变量，分数变化才能归因到模型本身。样例库的评测集有三百条问题，覆盖事实、概念和混合三类，任何模型都要在这三类上分别看分数，不能只看总分。

## 向量维度意味着什么

向量维度是模型输出向量的长度，直接决定了向量的表达能力和存储成本。维度越高，理论上能编码的语义细节越多，但存储和计算成本也越高，维度翻倍时，索引体积大致翻倍，相似度计算时间也接近翻倍。常见模型的维度分别是：MiniLM 的 all-MiniLM-L6-v2 输出三百八十四维，bge-small-zh-v1.5 输出五百一十二维，bge-base-zh-v1.5 输出七百六十八维，bge-large-zh-v1.5 输出一千零二十四维。维度从三百八十四升到五百一十二时，样例库的召回率从百分之七十一升到百分之七十六，提升五个百分点；从五百一十二升到七百六十八时，召回率从百分之七十六升到百分之七十九，提升三个百分点；从七百六十八升到一千零二十四时，召回率从百分之七十九升到百分之八十，只提升一个百分点。收益递减非常明显。存储方面，一百万个块用三百八十四维存储约需一点五吉字节，用一千零二十四维约需四吉字节，差距接近三倍。对中小知识库来说，五百一十二维或七百六十八维通常是性价比的拐点，一千零二十四维只在知识库主题非常多、语义区分很细时才值得。

## 上下文长度与切分的配合

Embedding 模型的上下文长度指它一次能处理的文本长度，超过的部分会被截断，截断掉的信息不会进入向量。MiniLM 的上下文长度为二百五十六个词元，bge 系列为五百一十二个词元。中文里一个词元大致对应一点五个到两个汉字，所以二百五十六个词元约对应四百到五百汉字，五百一十二个词元约对应八百到一千汉字。切分块大小控制在三百到八百字符之间，正好和这个范围匹配：如果块长八百字符，用 MiniLM 编码会截掉后半部分，块的后半段信息在向量里是缺失的；用 bge 编码则基本能完整覆盖。样例库的实测显示，块长五百字符时，MiniLM 的召回率为百分之七十，bge-small 为百分之七十六；块长八百字符时，MiniLM 降到百分之六十五，bge-small 保持在百分之七十五。差距主要来自截断。选型时要先看自己的块长分布：如果块长普遍在三百到五百字符，MiniLM 也够用；如果块长经常接近八百字符，或者表格、代码块较长，就该选上下文更长的模型。还有一种做法是编码时按句子切分再取平均，但这种做法会损失句子顺序信息，样例库测试后没有采用。

## 中文与英文模型的区别

中文和英文在 embedding 选型上差别很大，不能直接套用英文评测的结论。英文模型在中文问题上的表现通常明显下降，因为它的训练语料里中文占比低，对中文同义词、成语、专业术语的区分能力弱。样例库做过对照：一个在英文评测里分数很高的通用模型，在中文评测集上的召回率只有百分之六十二，比专门的中文模型低十四个百分点。中文模型 bge小型版 在中文评测集上的召回率为百分之七十六，在英文评测集上为百分之六十八；MiniLM 在英文评测集上为百分之七十三，在中文评测集上为百分之七十一。结论很直接：知识库以中文为主就选中文模型，以英文为主就选英文模型，中英文混合的库要选双语模型，或者按文档语言分两个索引。双语模型的代价是单语性能各降一到两个百分点，但省去了维护两套索引的成本。判断模型是否适合中文，除了看评测分数，还要看它对中文分词边界的敏感度：把一句话里的词换个顺序、换个同义词，好的中文模型分数变化应该在零点零五以内，差的模型可能波动零点一五以上。

## MTEB 评测怎么看

MTEB 是一套公开的 embedding 评测基准，包含检索、分类、聚类、相似度等多种任务，检索任务的分数最值得参考。看 MTEB 分数要注意三点。第一，只看和自己任务接近的子任务：做问答检索就看检索类任务的分数，分类任务的分数再高也没有意义。第二，看中文子集和英文子集要分开：bge大型版 在中文检索子集上的分数约为零点七一，在英文检索子集上约为零点六四；bge中型版 中文约为零点六八，英文约为零点六一；bge小型版 中文约为零点六四，英文约为零点五八；MiniLM 中文约为零点五九，英文约为零点六六。第三，MTEB 分数和自己知识库上的分数不完全对应，MTEB 高三分，在自己库上可能只高一分，也可能高五分。样例库的做法是先用 MTEB 缩小候选范围，筛出两到三个模型，再在自己的三百条评测问题上实测，最终按实测分数定。MTEB 还有一个作用是看模型的短板：如果一个模型在检索任务上分数高，在相似度任务上分数低，说明它适合找相关块，但不适合做精细的语义去重，这时去重阈值要放宽。

## bge 与 MiniLM 的区别

bge 和 MiniLM 是样例系统里最常对比的两个模型家族，区别体现在五个方面。第一是维度：bge-small 五百一十二维，bge-base 七百六十八维，bge-large 一千零二十四维，MiniLM 三百八十四维。第二是上下文长度：bge 五百一十二个词元，MiniLM 二百五十六个词元。第三是中文能力：bge 是面向中文优化的模型，在中文评测集上比 MiniLM 高五个百分点；MiniLM 是面向英文优化的模型，在英文评测集上比 bge-small 高五个百分点。第四是编码速度：在同一台四核机器上，MiniLM 编码一千个块约需九秒，bge-small 约需十四秒，bge-base 约需二十一秒，bge-large 约需三十四秒。第五是模型体积：MiniLM 约九十兆字节，bge-small 约九十五兆字节，bge-base 约四百四十兆字节，bge-large 约一点三吉字节。综合来看，中文知识库优先选 bge-small 或 bge-base，英文知识库优先选 MiniLM，预算充足且追求极限召回率时选 bge-large。样例系统的当前选择是 bge小型版，理由是它在中文召回率上比 MiniLM 高五个百分点，编码速度只慢五秒每千块，体积几乎相同。换模型不是一次性决策，知识库语言分布变了、延迟预算变了，都要重新对比。

## 双塔与交叉编码器的分工

Embedding 模型属于双塔结构：问题和文档块分别编码，编码过程互不干扰，编码好的文档向量可以提前存好，查询时只编码问题，再算相似度。这种结构速度快，适合从成千上万个块里粗排。交叉编码器属于单塔结构：它把问题和文档块拼在一起输入模型，让模型逐对判断两者是否相关，判断时能看到问题和块之间的细粒度交互信息。交叉编码器的准确率更高，但速度慢得多，不能对全库逐对打分，只能对粗排出的少量候选重排。两者的分工是：双塔负责召回，交叉编码器负责精排。样例链路里，双塔从两千个块里粗排取二十到五十个候选，交叉编码器对这些候选逐对打分，选出三到五块交给生成。这个分工的代价是交叉编码器看不到粗排之外的块，如果关键块在粗排里排第五十一名，重排再准也救不回来。所以粗排的候选数不能太小，二十个是下限，五十个是兼顾延迟的上限。

## 交叉编码器重排原理

交叉编码器重排的输入是一对文本：问题加一个候选块，输出是一个零到一之间的相关分数。模型内部用注意力机制让问题里的每个词都能看到块里的每个词，例如问题里的“限制条件”能对应到块里的“不适用于”“仅在……情况下”等表述，这种跨文本的细粒度匹配是双塔做不到的。重排模型 bge-reranker-base 的输入长度上限为五百一十二个词元，问题加块超过这个长度时，块的后半部分会被截断，所以块长控制在八百字符以内对重排同样重要。重排分数的分布比向量分数更集中：相关块的分数多在零点七到零点九五之间，不相关块多在零点零五到零点三之间，中间地带零点三到零点七的块最难判断，约占候选的百分之二十。样例系统对中间地带的块做二次处理：如果前五名里有分数在零点三到零点七之间的块，生成时会在提示词里标注其相关性存疑，让模型谨慎引用。重排模型的训练目标就是区分相关与不相关，它在样例评测集上把交给生成的上下文精确率从百分之六十八提升到百分之八十四，提升十六个百分点，是链路里单步提升最大的环节。

## 候选数与延迟代价

重排的候选数直接决定延迟和效果。交叉编码器逐对打分，候选数翻倍，延迟大致翻倍。样例实测的单对打分时间约为九毫秒，候选二十个时重排耗时约一百八十毫秒，候选五十个时约四百五十毫秒，候选十个时约九十毫秒。效果方面，候选十个时重排后的召回率为百分之七十八，候选二十个时为百分之八十四，候选五十个时为百分之八十七。候选从二十加到五十，延迟增加二百七十毫秒，召回率只提升三个百分点，性价比明显下降。样例配置是粗排取二十到五十个候选，常规取二十个，复杂问题取五十个，取三到五块交给生成。延迟预算紧张时，可以先对候选做一次向量分数截断：只把向量分数前三十名的块送进重排，而不是全部五十个，这样延迟从四百五十毫秒降到二百七十毫秒，召回率只下降一个百分点。还有一种做法是批量打分：把多个候选拼成一批输入模型，批量为八时，五十个候选的耗时从四百五十毫秒降到三百二十毫秒。批量大小要根据内存调整，批量十六时内存占用翻倍，但耗时只再降百分之十。

## 重排什么时候会帮倒忙

重排不是万能的，有三种情况它会帮倒忙。第一种是粗排质量太差：关键块根本不在候选里，重排只能在错误的候选里挑相对好的，交给生成的块全是错的，这时该修的是粗排，不是重排。第二种是重排模型和知识库领域不匹配：例如用通用领域训练的重排模型处理高度专业的内容，它对专业术语的细粒度匹配能力弱，可能把包含精确术语但措辞普通的块排在后面。样例库里出现过重排后精确率反而下降两个百分点的情况，原因是重排模型偏好语义流畅的块，压低了术语密集但句子较短的块。第三种是候选块高度相似：二十个候选里有十几个是近重复块，重排分数拉不开差距，排序接近随机，这时该先做去重，再重排。判断重排是否有效的标准很简单：在评测集上对比重排前后的上下文精确率和最终答案的忠实度，两者都提升才算有效，只提升精确率但忠实度不动，说明重排选出的块虽然相关，但没有带来新的关键信息。

## 重排分数的校准与使用

重排分数不是绝对的相关程度，而是模型在当前候选集合里的相对判断，直接拿分数当置信度很容易误判。同一块在候选质量高的一组里可能只得零点六，在候选质量低的一组里可能得零点九，分数变了，块本身的相关性并没有变。样例系统因此不用固定分数阈值决定取舍，而是用排名加相对差距：取分数前三到五名，同时要求第五名的分数不低于第一名的百分之五十，如果第五名分数过低，说明候选整体质量参差不齐，宁可少取一块，也不要把弱相关块硬塞进生成上下文。分数校准还要分问题类型看：事实类问题的重排分数区分度高，相关块与不相关块的分数差距平均为零点四五；概念类问题的区分度低，平均差距只有零点二五，概念类问题取块时要更依赖排名，而不是分数绝对值。还有一个细节是分数的稳定性：同一问题重复查询两次，重排前五名的顺序约有百分之十五的概率出现一位的波动，波动主要发生在分数差距小于零点零三的相邻块之间。生成阶段对这种波动不敏感，因为前五名整体集合基本不变，真正需要警惕的是前五名集合本身的变化，如果两次查询的前五名里有两块以上不同，说明粗排或重排的稳定性出了问题，要检查分词、编码或批量打分的实现。分数日志要完整保存，包括每条候选的分数、排名和最终是否入选，线上出现答案错误时，可以回溯是重排排错了，还是生成用错了。

## 模型更新与回归验证

模型不是选定一次就一劳永逸，知识库内容、问题分布和延迟预算都会变，模型也要定期复评。样例系统每季度做一次模型复评，流程和初次选型相同：固定切分、固定融合、固定重排，只换模型，在三百条评测问题上重跑。复评的通过标准是新模型的召回率比现用模型高两个百分点以上，同时延迟增加不超过百分之二十，两项都满足才考虑切换；只满足一项时保持现状。切换模型时要全量重建索引，因为不同模型的向量空间互不兼容，旧向量不能直接复用。两千个块的重建约需一分钟，一百万个块的重建约需八小时，重建期间要保留旧索引在线服务，待新索引验证通过后再切换，避免服务中断。切换后第一周要每天抽查五十条真实提问的召回情况，发现异常立即回退。模型版本、维度、上下文长度和切换日期都要记入变更记录，任何一次线上答案质量的波动，都能按记录定位到某次模型变更。重排模型同样要复评，复评周期可以比粗排模型更长一些，因为重排模型对领域变化的敏感度相对低一些，但一旦发现重排后的精确率连续两周下降超过三个百分点，就要立即启动复评。

## 选型与重排的落地清单

落地时按清单逐项确认。模型选型先定语言、再定维度、再定速度：中文库先试 bge-small 和 bge-base，英文库先试 MiniLM，实测差距小于两个百分点时选更快的，差距大于五个百分点时选更准的。上下文长度要和块长匹配，块长接近八百字符时不选二百五十六词元的模型。MTEB 分数只用来筛候选，最终决定看自己评测集上的分数。重排模型选和 embedding 同系列的版本，兼容性更好，分数口径更一致。候选数先取二十个，延迟有余量再试五十个，效果提升低于两个百分点就退回二十个。重排后只取三到五块，多取会稀释上下文，少取会漏信息。每次换模型或换重排配置，都要重跑三百条评测问题，记录召回率、精确率、忠实度和延迟四项指标，四项里任何一项恶化超过两个百分点都要复查。复查时先看是不是评测集本身变了，再看是不是切分或索引出了问题，最后才怀疑模型本身。很多看似模型变差的情况，其实是新入库的文档改变了词频分布，或者是某批问题表述方式变了。把排查顺序固定下来，可以避免反复换模型却找不到真正原因。选型文档要和评测记录放在一起保存，新人接手时先读选型理由和历次复评结论，再动手改配置，这样才不会把已经验证过的错误路线再走一遍。模型和重排配置要版本化记录，包括模型名称、维度、上下文长度、候选数和批量大小，线上出问题时能按版本回退。版本记录里还要写明切换原因和评测分数，下一次复评时可以直接对比历次数据，不用重新翻找旧的实验记录。
